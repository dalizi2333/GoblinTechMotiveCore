# 模块子实体架构总结

## 核心原则

- `OfferingBlessingManager` 是抽象接口管理器，只认 Divine 单位
- 各模块内部处理 Divine 与外系统的转换
- 每个模块可持有独立子实体（BlockEntity / SimulatedDevice 等）
- 方块破坏时 `OfferingBlessingManager.destroy()` 统一销毁所有注册子实体

---

## 四大模块实现方案

### 1. StressOfferingModule（应力献祭）

**子实体**: `KineticModuleBlockEntity extends KineticBlockEntity`

**依赖系统**: Create 应力网络

**工作原理**:
- 模块安装时创建 `KineticModuleBlockEntity`，手动 `setLevel(level)` + 注册到 tick 循环
- `SmartBlockEntity.tick()` 首次调用 `initialize()`，`KineticBlockEntity.tick()` 自动调用 `attachKinetics()` 接入应力网络
- 模块拆卸时 `remove()` + `getOrCreateNetwork().remove(this)` + `detachKinetics()`

**转换**: Divine ⇄ SU（`scheduleWorking(su)` / `getSpeed() * torque`）

**IOfferingModule 实现**:
```java
class StressOfferingModule implements IOfferingModule {
    KineticModuleBlockEntity kineticBE;

    ActionResult offer(float throttle) {
        float divine = maxDivine * throttle;
        float su = divineToSU(divine);
        kineticBE.scheduleWorking(su);
        return SUCCESS;
    }

    ActionResult getMaxOffering() {
        float availableSU = abs(kineticBE.getSpeed()) * torque;
        return suToDivine(availableSU) >= minRequired ? SUCCESS : FAIL;
    }
}
```

### 2. ThunderOfferingModule（雷电献祭）

**子实体**: `ThunderOfferingDevice extends SimpleElectricalDevice`（CEE SimulatedDevice）

**依赖系统**: CEE 电路模拟

**工作原理**:
- 纯数据对象，由 `DevicesSavedData` 管理，不需要 Block/BlockEntity
- 4 对可调电阻，8 个电线接入点：`resistor(0,1,r1)`, `resistor(2,3,r2)`, `resistor(4,5,r3)`, `resistor(6,7,r4)`
- `preTick(BridgeCollector)` 注册电阻，`postTick(SimulationResults)` 读取电压差
- 安装时注册到 `DevicesSavedData`，拆卸时 `onDestroy()`

**转换**: Divine ⇄ 电阻发热（电压差 × 电流 → 功率 → Divine）

**NodeConfigurator（8 个电线接入点）**:
```java
NodeConfigurator THUNDER_4PAIR = new NodeConfigurator.Builder()
    .add(3, 12, 4)   .add(3, 12, 12)   // pair 0
    .add(7, 12, 4)   .add(7, 12, 12)   // pair 1
    .add(9, 12, 4)   .add(9, 12, 12)   // pair 2
    .add(13, 12, 4)  .add(13, 12, 12)  // pair 3
    .simple();
```

### 3. FuelOfferingModule（燃料献祭）

**子实体**: 无独立子实体，持有自备 `EnergyStorage`

**依赖系统**: GTM 能量系统

**工作原理**:
- 自持独立能量缓存，不依赖宿主 `NotifiableEnergyContainer`
- 持有燃料配方类型（`GTRecipeType`），内部 tick 时消耗燃料 → 补充自持 EU
- 被 `OfferingBlessingManager.offer(throttle)` 调用时，消耗自持 EU → 回传 Divine 给宿主

**转换**: 燃料 → EU（内部），EU → Divine（offer 回传）

**IOfferingModule 实现**:
```java
class FuelOfferingModule implements IOfferingModule {
    // 自持能量缓存
    EnergyStorage selfEnergyCache;
    GTRecipeType fuelRecipeType;

    // 内部 tick：消耗燃料 → 补充自持 EU
    void internalTick() {
        if (selfEnergyCache.getEnergyStored() < maxEnergy) {
            // 查找燃料配方，消耗物品，补充能量
            burnFuel();
        }
    }

    // 被宿主调用：消耗自持 EU → 回传 Divine
    ActionResult offer(float throttle) {
        float divine = maxDivine * throttle;
        long eu = divineToEU(divine);
        if (selfEnergyCache.extractEnergy(eu, true) >= eu) {
            selfEnergyCache.extractEnergy(eu, false);
            return SUCCESS;
        }
        return FAIL;
    }

    ActionResult getMaxOffering() {
        return selfEnergyCache.getEnergyStored() > 0 ? SUCCESS : FAIL;
    }
}
```

### 4. ThrustBlessingModule（推力祝福）★

**子实体**: `SmartBlockEntity` + `BlockEntityPropeller`（来自 sable-companion）

**依赖系统**: Simulated-Project 物理系统（不接入 Create 应力网络）

**工作原理**:
- 宿主通过 `bless(throttle)` 传入 Divine → 模块内部转换为推力
- 不继承 `KineticBlockEntity`，不接入旋转力网络
- 实现 `BlockEntityPropeller` 接口，添加 `PropellerActorBehaviour` 作为行为组件
- `getThrust()` 直接由当前 Divine 输入量计算，不依赖外部转速
- `PropellerActorBehaviour.pushEntities()` 自动处理飞行器物理空间变换

**转换**: Divine → 推力（单向消耗）

**核心接口**:
```java
class ThrustBlessingModule extends SmartBlockEntity
        implements IBlessingModule, BlockEntityPropeller {

    PropellerActorBehaviour propellerBehavior;
    float currentThrust;    // 由 Divine 输入计算
    float currentAirflow;   // 由 Divine 输入计算
    boolean active;

    // BlockEntityPropeller 契约
    double getThrust() {
        return currentThrust;
    }

    double getAirflow() {
        return currentAirflow;
    }

    Direction getBlockDirection() {
        return Direction.UP;
    }

    boolean isActive() {
        return active && currentThrust > 0;
    }

    // IBlessingModule 契约
    ActionResult bless(float throttle) {
        float divine = maxDivine * throttle;
        currentThrust = divineToThrust(divine);
        currentAirflow = divineToAirflow(divine);
        active = currentThrust > 0;
        return active ? SUCCESS : FAIL;
    }

    ActionResult getMaxBlessing() {
        return SUCCESS;  // 推力模块始终可用（无外部依赖）
    }
}
```

## 子实体类型汇总

| 模块 | 接口 | 子实体类型 | 依赖 mod 系统 |
|------|------|-----------|--------------|
| StressOffering | `IOfferingModule` | `KineticModuleBlockEntity` | Create 应力网络 |
| ThunderOffering | `IOfferingModule` | CEE `SimulatedDevice` | CEE 电路模拟 |
| FuelOffering | `IOfferingModule` | 自持 `EnergyStorage` | 无（内部管理） |
| ThrustBlessing | `IBlessingModule` | `SmartBlockEntity` + `BlockEntityPropeller` | Simulated/Sable |
